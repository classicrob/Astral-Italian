# Native MEM1/MEM2 reservation

Native ResTIMG records keep signed 32-bit header-relative image/palette addresses. Startup replaces WipeModelCloud's IndDummy with CaptureScreenDirector's screen texture. A bounded M1 diagnostic classified its source header/image as MEM2 and destination model header as MEM1; capture construction had a current JKR heap, host routing off and a registered game thread. No host fallback was observed. A separate clean startup aborted at the existing J3DTexture range check; that failed run recorded MEM1 at 0x178000000 but did not retain its exact other addresses. The successful diagnostic's arenas were adjacent at 0x300000000/0x308000000. Full bounded evidence, including this distinction, is in scratch-port/yoshi-tcg21/timg-arena-evidence.json.

Independent mmaps cannot guarantee the cross-arena distance required by these game wire offsets. The shared native arena code therefore reserves one 512 MiB range: MEM1 remains 128 MiB at base; MEM2 remains 256 MiB at base + physical address 0x10000000. The intervening 128 MiB remains PROT_NONE and is rejected by arena translation/region guards. Both actual arenas are readable/writable. Boot reservation, capacities, boot info, address translation and fail-fast behavior are retained. Mapping/protection failure aborts with no fallback; the J3DTexture panic is unchanged. This applies to every native host, independent of ASLR placement or toolchain.

The largest possible cross-arena distance is 512 MiB - 1 (536,870,911 bytes), fitting signed 32-bit offsets in either direction. Production native memory tests check the exact MEM2 offset, capacities, boot aliases, gap classification, end writes, maximum distance, SDK alignment/coalescing and existing failed-allocation behavior. Runtime receipts for three fresh startups and the corrected Yoshi retry are recorded separately. No Wii/game/J3D wire layout changes or graphical differential acceptance are claimed.

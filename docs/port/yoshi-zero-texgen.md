# Zero-texgen alpha-shadow draws

The YosshiHomeGalaxy crash came from `MR::drawModelAlphaShadow(J3DModel*)` through `J3DShape::drawFast` (FIFO owner 91 in the M1 diagnostic). The pass sets zero texgens while inheriting a TEV order naming coordinate/map 0. The snapshot copies no texgens, leaving Aurora's inactive source sentinel 21, but texture-use analysis previously attempted to generate it.

This is original behavior, not native material-count truncation. Original SB4E01 DOL function 0x800222D0 loads argument 0 at 0x80022328 and calls GXSetNumTexGens at 0x8002232C (target 0x805CBA00), then draws the shapes at 0x80022414. YoshiShadow.bdl's three MAT3 materials also store a zero generator count. The raw archive scan covered 2,524 archives and 1,521 models/MAT3 blocks without parse errors or source 21. The inactive RingBeamerAreaObj texcoord record with source 255 remains separately recorded.

The copied pipeline now models our differential oracle, [Dolphin 409881c3 PixelShaderGen.cpp](https://github.com/dolphin-emu/dolphin/blob/409881c34357d0f105fd473167d15ab0bd9c1628/Source/Core/VideoCommon/PixelShaderGen.cpp#L1274-L1291): zero texgens skip the direct sample and supply zero RGBA texture inputs. Replacing every TEXC/TEXA color operand and TEXA alpha operand with ZERO is equivalent for every swap table because permuting zero RGBA leaves zero. This applies to every TEV stage, including disabled orders. A positive generator count with a non-NULL out-of-range TEV coordinate instead selects coordinate 0 (lines 1047–1052). The existing indirect-coordinate rule is retained (lines 1804–1809 and 1824–1840), including indirect texture reads at zero coordinates when no texgens exist. Dolphin documents remaining uncertainty about retail hardware; this change claims pinned-emulator compatibility.

The fix belongs to the native generated-source patch chain against Aurora 08122911e8621acb7ded6563813b264bec1494b5. It uses the actual GX count while constructing the pipeline; no count is inferred from sentinels. Positive-count NULL-coordinate stages stay byte-identical. Live state and genuinely invalid enabled texgen sources retain their existing fatal validation. Normalized draws have different pipeline hashes; existing cached entries should not be treated as equivalent proof. No Wii source or ABI changes.

Validation uses the production snapshot builder and shader generator: all operands/multiple stages/nonidentity swaps, disabled orders, direct no-sample and indirect-preservation checks, positive fallback, valid-stage preservation, and invalid-enabled-sentinel preservation. Runtime evidence and binary hashes are recorded separately in private M1 receipts and the small report under scratch-port/yoshi-tcg21/. Raw assets and gameplay logs are not part of this change.

M1 validation (2026-10-20): the clean fixed executable SHA256 is `1d57e25ddcb3b54562dcff6bb313373626d671787390a5669405d1460ad19168`, built from ee0732c0 plus the 1048d955 support prerequisite and exactly the four delivered native fix files. Production `petari_gx_shader_tests` passed. YosshiHomeGalaxy scenario 1 ran 330 seconds with a fresh profile/cache and mods off, then handled controlled termination with exit 0. DigMineGalaxy scenario 1 ran 120 seconds the same way, exit 0; telemetry contains 6,772 frames, including 6,241 gameplay frames. Neither run reported the texgen fatal. A prior second-galaxy attempt used the nonexistent SkyIslandGalaxy name and exited 2 before loading; it is retained as a failed attempt, not counted as a smoke. These are bounded crash/idle regressions, not graphical differential acceptance. PORT cancelled optional Dolphin instrumentation after accepting the original DOL evidence.

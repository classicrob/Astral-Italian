## Time and phase contract

`aurora_frame` reads the existing shared `PetariNative::LatencyProbe::frame` atomic. `native/gx/present/present_host.cpp::composeFrame` increments it unconditionally after the seam's route recording, including when the latency probe is disabled. It is a presentation-choice ordinal, not a VI count, input-script counter or guaranteed scan-out frame.

`[wm-route-align]` is emitted inside `RouteRecordWriter::write`, immediately before its original `mFrame++`. It logs the actual next CSV `frame` and the shared ordinal, with `phase=seam-before-route-write`. No offset is inferred. Input scripts and CSV contents are unchanged. Draw precedes game update; the seam route row can therefore describe a later state than the draw tuple bearing the same ordinal. Each multi-line observation pins the ordinal in thread-local scope; `seq` is an atomic monotonic event number, and primary events identify a process-local host thread hash. Preserve phase and chronological `seq`; never equate these samples silently. The counter is not reset across scenes. Owner initialization gets an observation epoch.

## Initialization, lifetime and thread ownership

The consumed-flags hook touches no owner graph. It clears the diagnostic ready-owner identity. Only the hook AFTER both original Grand and owner sequence initialization return publishes that identity. `key`/`tuple`/actor walks refuse an owner lacking this actual completion witness and report unready. GameScene destructor ENTRY retires the identity and model joins BEFORE any graph release, without dereferencing the owner; the owner destructor has an additional fallback reset. The owner destructor alone is not a guaranteed scene-lifetime hook: SceneObjHolder stores raw object pointers. Post-init checkpoints inspect graph/scalars only; actor/model traversal and final camera/projection reads happen in the real GameScene draw path, which the scene controller executes only in Normal after async initialization completes. `WorldMapOwnerContext` and `WorldMapSequence` constructors leave some later fields uninitialized, so null/count plausibility alone is deliberately insufficient.

`GameSystemSceneController.cpp:363-375` initializes the scene through the priority17 asynchronous function worker. Owner init/initial camera enqueue hooks can run there. Owner movement, nerve bodies, GameScene draw/J3D CPU submissions and route writing run on the game/main path. `native/platform/os/os_thread.cpp` serializes game execution through its CPU baton. Route recording is before `gRelease.begin` in frame_seam.cpp; it still holds that baton. These hooks do not run on Aurora's FIFO/render worker. Thus mutable diagnostic ready/model/budget/phase state relies on existing game-code baton serialization, not on the event atomic for graph safety. Host compose can advance the existing latency atomic while the init worker runs, which is why each multi-line observation pins it once. Counts/joins do not keep heap ownership alive and must not be called by new host/renderer callbacks outside this contract. Thread IDs expose an unexpected caller; an atomic sequence alone does not make arbitrary concurrent graph traversal safe.

Camera enqueue/effective queue inspection uses the actual `CameraManEvent::mHolder` passed by that fully constructed provider. It avoids finding a possibly different global holder during scene initialization. Null FIFO slots do not read their uninitialized frame/argument members. Partial/unready output and budget loss are explicit.

## Records

- `wm-consume`: exact latched original event query, whether the original conditional after-FileSelect query was evaluated, its value if available, and consumed `startAtMap`. The original short circuit and Wii statement remain intact. `raw-after-now` is a separate observation. `wm-flags` brackets the existing clear.
- `wm-owner`, `wm-state`: local/grand world identities, shared node/next/direction, saved local/grand nodes, owner/result/Grand sequence nerves, raw CURRENT and PENDING, registered keeper state, dead flag and actor step/current/pending. Pending state can coexist with the old current nerve during `Spine::changeNerve`; this is expected. Names are source identities, not claims about retail dispatch.
- `wm-body`: actual source function entered, sampled at steps0/6/20/60 and every60 thereafter. TU13 successful restoration and kill-after-dead, plus TU14 appear-before-local-camera, have explicit checkpoints. TU14 inline Wait execution is observed without changing its call. Body absence alone is not proof of a skipped path.
- `wm-request`: actual local or Grand camera provider/name/ID/frames/actor/target/node/layer, before the original request. `wm-camera-chunk`: effective chunk and BOTH current/queued slots for BOTH priorities, including name/type/zone, target-argument identities and frames. Enqueue and effective changes are observed.
- Selected draws: eye/up/forward, active target, holder actor target, interpolator watch/timer/FOV, final FOV/near/far/aspect, view/projection matrices and logical dimensions. Each map's current-node lookup checks its own bounds and reports its anchor/view/clip coordinates.
- `wm-actors`: separately local/grand parts, marks, galaxies, routes and attached actors, plus local backdrop/children: total/alive/hidden/clipped/null. Missing arrays and invalid counts are explicit. State counts do not establish rendering.
- `wm-submit`: joined J3D model and unique node submissions, separately main and mini pass. Hooks are inside nonhidden shape-packet paths, including J3DModelX. These establish CPU submissions, not rasterization, visibility, pixels or a GX worker success. Unjoined models and particle-only content are outside these counts. Model joins are capped4096 and overflow is reported.

Draw snapshots occur on the first four world-map draws, state/chunk/node changes, and each60 ordinals. State-update snapshots occur on changes/every60. Transition/request events are capped48 per ordinal; `wm-budget` explicitly marks exhaustion and reports drops. A trace with drops/unready fields cannot use missing events as evidence. There are no FIFO worker hooks in this package; the older broad `c2934ead` scratch diagnostic is separate.

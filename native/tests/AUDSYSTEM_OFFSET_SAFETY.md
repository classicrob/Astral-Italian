# Native AudSystem restricted-sound counter regression

Run `python3 native/tests/audsystem_offset_tests.py`. The test includes the canonical owning AudSystem header and measures the actual native layout in a small ASan/UBSan-enabled executable. It does not construct or execute AudSystem or replace any audio provider. It separately compiles the complete production AudSystem.cpp to LLVM IR and checks the setter's single unchanged signed32 input/store, canonical msBasic global and canonical mRestrictedSoundFrames field address. The original raw0x834 write, a neighboring counter write and an input-narrowing mutant must all fail. No fabricated object lifetime or aliased memory fixture is used.

Actual MWCC Wii/1.0 measurements bind the canonical field to0x834 with width4. On the tested native M1 ABI, the same declaration places it at0x9C8 with width4; the inherited JAUSoundMgr base occupies0x9A8. The old native raw0x834 instead overlaps mSeMgr.mParams.mParams.mFxMix, a floating-point field. It is an in-object wrong-field write that need not trigger a sanitizer. The native fix uses the existing named field; it does not encode a new offset or change any header/layout. The Wii statement remains verbatim under #else.

The actual DOL setter loads msBasic and stores its full32-bit argument at+0x834, with no branch or callee. Two direct DOL callers pass2 during the star-clear sequences; they do not restrict the setter's public s32 domain. The native IR test follows the input word directly to the correct field, including negative and full-width bit patterns. The existing singleton-validity precondition, counter countdown, restricted-sound tests, calls and all floating-point arithmetic remain unchanged. No null default, runtime audio/gameplay completion or whole-audio-system sanitizer execution is claimed.

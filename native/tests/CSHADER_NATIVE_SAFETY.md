# Native CShader packed-read and null-image regression tests

Run `python3 native/tests/cshader_native_safety_tests.py` on M1. It compiles the full production CShader translation unit with ASan, UBSan and float-cast-overflow checks. Its actual getCount helper and CLengthMap constructor/setter/refer methods execute directly. The vertex and border read statements are extracted verbatim into accessors, so all offsets and alignments can be tested without constructing a model/renderer graph. These tests do not execute complete makeIndexData/checkBorderVtx traversal, malformed resource handling or the renderer. No game providers are stubbed or redeclared.

The two display-list count reads and four vertex-index reads are unsigned16 big-endian in the Wii DOL (LHZ/LHZX), even at odd byte offsets. Native code uses existing PetariNative::readU16BE for those six expressions; descriptor interpretation, strides, offsets, loop conditions and index writes remain unchanged. All65536 counts at four byte alignments, distinct high-byte vertex indices and odd/even strides are checked. Mutants restoring each original cast must fail. An alignment-safe reversed-endian mutant must also fail.

The length-map constructor's target ADDI/STW stores image address+0x20 before the null check. For null, it stores address value32; setLengthMap sets the inactive byte to1 and refer returns1.0f before dereferencing either pointer. Native uintptr_t arithmetic preserves that address word without performing pointer arithmetic on null. The texture header remains32B. No null-zero value was invented. Tests check that exact field value, the inactive short circuit with nonfinite UV inputs, valid I8 sampling, unsupported formats and the setter's address-retention behavior. Both the original null pointer arithmetic and an invented null-zero guard are negative controls.

Only the packed reads and constructor address calculation change natively. Existing floating-point grouping, precision, wrapping/conversions in getTexelOrder and calc, texture-header normalization, data bounds and resource lifetimes are outside this repair. Tests use host-normalized ResTIMG headers, as the owning SDK header requires. Both Wii code branches and complete non-debug Wii object contents must remain unchanged.

# Independent dispatch import and final-hook contract

This branch is a review proposal. `dispatch_import.py` is an offline library; it
has no CLI, certificate installer, production-hook mutation or landing action.
Neither `remoteproof.py` nor `proofland.sh` is changed. Full-package qualification
and an explicit installation/allocation review remain required. Synthetic tests
and six-object component review do not establish a full proof or runtime result.

## Authority and modes

The operator supplies the original canonical spec FILE bytes, independently
reviewed TU13/TU14 canonical plan hashes, exact caller-contract hash, proof host,
AFTER revision and local verifier-file hash map. These are not receipt fields
that can authorize themselves. Source/config bytes come from immutable local Git
objects through `GitSources`, never from uploaded scripts. The private original
DOL is read only in memory and must match the fixed original hash. No instruction
payloads or assets are emitted by the adapter.

The operator must separately qualify command-token expectations for both complete
phase graphs and both source-control targets using independent official graph
construction/dry-run inspection. The adapter rejects missing/empty expectations;
it never treats uploaded `commands.txt`, recipe, helper, certificate or reported
`rejected=true` as executable verifier authority. This independent command
qualification remains an actual-import prerequisite, not a passing placeholder.

Only schema1 `DISPATCH_PROOF_V1`, status
`COMPLETE_AWAITING_INDEPENDENT_IMPORT`, is admissible. The exact outer field set
excludes generic PASS, Mario52/native exemptions, equivalent-base substitutions
and all other modes. Unknown/missing fields reject. The original canonical spec
and both operator-pinned plans stay unchanged. No generic hookproof certificate
is emitted or reused.

## Independent checks

The adapter confines/hash-checks metadata, rejects duplicate JSON keys/nonfinite
values, and accepts primary EXACT4855 regular ELF members plus secondary EXACT3
TU14 control members. Traversal, symlink components, tar links/directories, PAX
metadata, duplicate/missing/extra members, overwrites and hash/size mismatches
reject. Temporary extracted files are owned by the verifier and cleaned on exit.

It independently re-reads every object through the reviewed occurrence-keyed
comparator, enforces2424 strict objects, and normalizes only the exact four
reviewed execute value/size records. Full named/local/config alias references
across2426 objects and entire execute spans must equal the four owning zero-addend
vtable slots. Wrong target/kind/addend/slot, midbody aliases or additional references
reject even when present in BOTH phases. Original DOL singleton/ctor/vtable/Spine
chains and actual object ownership are decoded with the pinned local decoder;
known-bad BEFORE must exhibit the two reversed owners per scope.

Both actual-source perturb/restore controls must bind the reviewed append bytes,
local Git source hashes, exact object baseline and byte-identical restoration,
independently expected compiler commands and every header/dependency hash. All26
separate real-ELF negative artifacts are independently reconstructed byte-for-byte,
then rejected by semantic comparison (alias/slot negatives also by the census).
All8 config negatives are independently reconstructed/rejected. Missing controls,
stale metadata, wrong paths or unsupported receipt shapes reject. Uploaded
producer helpers are never imported, evaluated or executed.

The recipe, source/config, phase graphs, object inventories, command/header/tool
provenance, secondary archive and tagged certificate are joined to operator pins.
A verified result is `VERIFIED_NOT_LANDED`; it is not promotion or runtime approval.
Actual full proof/package execution remains unrun until a separately allocated
package is available and the importer itself has independent review.

## Exact final hook proposal, not installed

After independent verification, retain the canonical import-record SHA externally
in the reviewed landing invocation. Immediately before any future landing, read
that record and re-capture the current canonical spec and verifier tool hashes.
`final_hook(record, pinned_record_sha256, current_spec, current_tools, current_tip)` requires
exact record/hash/base/tip/source/tool/mode equality and returns only
`FINAL_CONTRACT_MATCH_ONLY`, `landing_authorized=false`. Any drift rejects.

A future separately reviewed production wrapper must additionally confirm the
actual base/tip and exact staged trees, leave the canonical spec/cert immutable,
use a distinct dispatch-tagged final certificate path, exclude concurrent exception
modes, recheck tool/input hashes immediately before the normal incremental Wii
guard, and call land.sh only under its normal allocation. It must not copy a
DISPATCH_PROOF_V1 certificate into the generic unchanged-proof certificate path.
This branch intentionally does not install that wrapper or weaken the existing
generic gate. Final-hook record integrity is pinned by the operator; an unpinned
JSON file is not an authorization token.

Run asset-free controls:

```
python3 -m unittest discover -s tools/team -p test_dispatch_import.py
```

The tests qualify transport, synthetic semantic inventory, failure rejection and
pure hook contracts. They do not certify a real2426-object package, candidate
compilation, source perturb execution, original-DOL runtime behavior or promotion.

## Independent command and phase-root context

`dispatch_commands.py` derives every compile token from the operator-pinned
canonical unit options and the official configuration's unit order. It does not
read producer command receipts. Qualification compares this derivation with an
in-memory expansion of the pinned official `configure.py`/`tools/project.py`
graph, using only Ninja's `-t commands` metadata operation. No compiler is run.
POSIX `shlex.split` is the only command normalization: row order, token order,
absolute tool paths, phase-relative source/output names, Shift-JIS wrapping,
language selection, dependency transformation and assembler DTK fixup stay exact.
Before/after source bytes and trees are separately bound even when commands match.

For `33e71ee880b426c0c7da03a724377200e874c417` to
`22d4c005612f83dc70a2a187c2b1a426ada66296`, canonical spec
`3b0975d48ca4354862814f13de004121fb16fbc1b90f87fb8e9f78a65155f8d9`
yields 2,424 MWCC rows and two GNU assembler/DTK-fixup rows. Independent expansion
matches graph `67e483c6dbb4b864718a842a7acaaed75d6284ca3f0ed30f823c317bd905de69`.
The private operator packet is
`~/MacioGalaxy2-team/scratch-port/solL/dispatch-operator-expectations-r1/`;
`command-tokens.json` has SHA-256
`d41b350898e0ccb1f15fd59e0e24ef0d32b6eaf5ffbb471f7d19000bf97dacb0`.
It includes exact per-target TU13/TU14 source-control commands. The local
metadata-only Ninja and the target M1 execution Ninja have different hashes;
the packet records both without treating version strings as byte identity.
The first metadata preflight that conflated these identities is preserved.

The operator trust dictionary now also requires exact `phase_roots.before` and
`phase_roots.after` absolute paths under one reviewed `execution` directory.
Dependency normalization strips only that exact corresponding root. Foreign
prefixes, opposite-phase roots, dot traversal and noncanonical paths reject.
These roots remain unbound until the final caller/output allocation is reviewed.
The returned import record hashes command tokens and roots together as
`operator_context_sha256`; the pure final-hook record retains this binding.
`dispatch_commands.py` is included in verifier tool hashes.

This command qualification grants no full build, archive import, final hook or
landing authority. Full object evidence must still satisfy the separate TU13
and TU14 operator plans, pinned original-DOL ownership, all 2,426-object
named/local/absolute/config reference closure, 2,424 strict object comparisons,
both actual source perturb/restore controls, 26 ELF and eight config negatives,
and the separately transported TU14 control archive. The caller's fixed tool
environment, final monitor, full package and independent import remain subject
to their own source review, actual qualification and explicit allocation.

## Final monitors and detached publication (source-only extension)

Both `receipt.monitors.execution` and `.packaging` are mandatory. Each contains
confined, hash-bound `budget`, `cleanup` and `completion` artifact records.
`dispatch_monitors.py` checks successful **final** teardown reports, exact byte
hash joins, a shared original baseline/root, finite monotonic elapsed times,
reviewed stage limits and the reserved floor/growth policy. The execution
completion binds the canonical actual-result hash; packaging binds both final
encoded archive hashes. Empty samples, failed/uncertain cleanup, EPERM failure,
rebased packaging budgets, stale or reused artifacts and inconsistent reports
reject. This validates reported sampled observations; it grants no filesystem
quota or syscall latency guarantee and cannot substitute for the reviewed
chosen-context lifecycle qualification.

The reviewed caller contract must add `packaging_seconds: 600` and
`terminal_metadata: {maximum_allocated_bytes: 16777216, reserved_bytes: 16777216,
scope: "monitor-copy-and-terminal-receipt-transfer-only"}`. Both monitored stages
reserve those bytes above the 50 GiB floor and below the 4 GiB growth ceiling.
They retain the 0.25 s sampling interval, finite 200,000-entry/2 s scan policy,
2,400 s execution work limit and four-second cleanup grace. The exact completion
fields and rejecting controls are defined by `dispatch_monitors.py` and its
asset-free tests. Unknown completion fields reject.

The terminal receipt cannot hash its own final monitor. Instead the operator
trust dictionary independently pins `terminal_publication_sha256`, and the
importer reads `terminal-publication.json` from the import root. This detached
sidecar binds final raw receipt/transfer hashes, the six final monitor files,
exact eight-file terminal metadata inventory, original baseline and host
allocation/free-space observations. It excludes its own hash and reserves
64 KiB for its final publication. The producer must enforce that reserve when
publishing; the importer checks the supplied bytes against the external pin,
metadata hashes/lengths, original-root growth/floor and the declared measured
metadata-plus-final-file reserve. Receiving-filesystem allocation is not used as
a substitute for the original host observation. The actual terminal publisher
and chosen-context caller still need independent review and actual qualification.
The operator context in the final import record binds the detached sidecar pin
alongside command tokens and exact phase roots.

No live full caller, actual full package, production import/hook or landing is
qualified by this extension. Missing final reports or disabled caller contracts
remain rejection conditions; there is no compatibility bypass for older drafts.

# Source-bound GX freeze gate helpers

Experimental operator-run tooling; no game source, input assets, logs, cache data or screenshots are included. The game checkout and frozen binary are independently pinned by the gate CLI. This branch is separate from the game proof base and is not a landing or runtime acceptance claim.

`promotion52.py` runs the port checklist with private output profiles and a verified private unlocked-save fixture. It requires explicit source, executable SHA256, renderer key and the operator window environment. Select `--cases worldmap --modes fresh,warm --isolated-cache` for a new private fresh/warm cache pair. `normal-boot-ui` omits --stage and must be driven through the actual file-select UI; `normal-route` uses the explicit stage adapter and never substitutes for that UI coverage. The current operator fixture/script locations remain under scratch-port/solL and private gamedata; these external prerequisites must exist and pass their own receipts.

`cache_gate52.py` opens only existing matching-key databases with SQLite mode=ro, query_only and a read transaction, so committed WAL content participates. It checks the pipeline table column identity, Aurora schema and exact renderer-key row before returning a real count. Empty counts are not a warm-cache pass; missing tables/keys are errors. It never treats existence as persistence evidence. The six controls in test_cache_gate52.py include an actual committed WAL where the old immutable reader sees zero rows and the corrected reader sees one.

`write-live-pointer52.py` requires an explicitly confirmed actual CUA observation, a still-live owned app PID, multiple valid recorded pointer positions and two private captures. It writes monotonic time/frame provenance. The gate rejects observations outside the live case interval. Its geometry documents the currently measured 2x server window; re-observe and update it if the window geometry changes. It does not synthesize pointer input or certify a screenshot automatically.

The first map gate receipt failed due to missing timely pointer JSON and an immutable SQLite reader that ignored WAL. That failed receipt remains unchanged. Corrected reruns are required. Registry labels mean top-level gameplay mods OFF; OdysseyJumpDive defaults ON but is inert while OdysseyMovement is OFF. Cappy cases intentionally enable Movement, Cappy and the default JumpDive option. No renderer-equivalence, sanitizer-clean or full-progression claim follows from these helpers.

Normal boot uses ordered Title/FileSelectStart/FileSelect/DemoStartWait milestones plus the actual live 242-star map witness and no --stage argument; the direct-stage adapter still requires OpenFile. These paths have different source milestones and are never substituted. The original normal-UI failed receipt is preserved. Its prior normal_route_visual field measured host input only; future checks name that normal_route_host_observation and separately require normal_route_visual_acceptance. Explicit accepted=true review must bind source, binary, case, mode, exact live pointer-observation hash/PID/time and both current capture hashes. Missing, stale, mismatched or rejected review fails aggregate acceptance even if all runtime/load checks pass. No existing failed visual review is rewritten.
